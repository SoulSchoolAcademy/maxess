## SOURCE-OF-TRUTH ACTIVATION

Before changing anything, explicitly establish:

**SOURCE → GENERATION/BUILD → DEPLOYMENT → PUBLIC/USER-FACING ENTRYPOINT**

A filename is not proof of authority.

A large file is not proof of authority.

A file named FINAL/MASTER/10/10 is not proof of authority.

The registry and verified deployment path determine authority.

## BASELINE ACTIVATION

Before execution, capture enough state to prove whether a real change occurred.

At minimum identify:

- current artifact/version;
- source path;
- current content/hash when available;
- existing sections/components;
- protected functionality;
- known defects;
- requested delta;
- acceptance criteria.

## LEARNING ACTIVATION

After meaningful work:

1. Record material observations.
2. Identify what worked.
3. Identify what failed.
4. Diagnose root causes.
5. Record reusable lessons.
6. Create safeguards when warranted.
7. Update daily synthesis when closing the day.
8. Promote durable learning only when justified.
9. Record system evolution when the operating system itself should change.

## FINAL ACTIVATION QUESTION

Before delivery, ask:

> **Did we merely produce an output, or did we improve the actual system and make the next execution more likely to succeed?**

The goal is not one lucky excellent output.

The goal is a system that produces exceptional results consistently.
