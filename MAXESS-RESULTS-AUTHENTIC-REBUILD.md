# MAXESS Results — Authentic Rebuild

Status: **NEW CANONICAL CANDIDATE — NOT YET CLAIMED 9.5+**

This rebuild intentionally starts fresh rather than patching an older Results page.

## North Star

The Results experience must move a person through:

**RESULT → RECOGNITION → PATTERN → MEANING → LEVERAGE → PATH → NAYA → ACTION**

The page is a personalized diagnostic experience, not a report and not a marketing dashboard.

## Architecture

The assessment engine owns truth. The renderer owns presentation.

`ASSESSMENT ENGINE → AUTHORITATIVE MAXESS_RESULT → RESULTS RENDERER → NAYA → NAYANET`

The renderer refuses to invent a score. It accepts `window.MAXESS_RESULT` (or a JSON result-data element) and renders from that contract.

## What is deliberately different

- Fresh visual and interaction architecture rather than additive overrides.
- No hard-coded 82/85/90 demo score presented as real user data.
- Five-dimensional fingerprint is a primary product moment.
- Strength and leverage are treated as decisions, not just metrics.
- Dimension relationships are explicitly represented.
- The 18 pathway library is connected to the diagnostic outcome.
- Naya is a guide transition, not a premature sales interruption.
- Mobile is designed as a first-class experience.
- Reduced motion, focus states, keyboard access, print, and no-result safety are included.
- The page is configuration-driven so the assessment engine remains reusable.

## Not yet a release claim

This branch does **not** call the page 9.5, 10, AAA, final, or production-ready. Those labels are earned only after rendered verification, data-contract integration, functional QA, accessibility review, responsive review, and a ruthless final score against the complete MAXESS rubric.
