# MAXESS Master Context Knowledge Bank

## Operating Purpose
This document is the persistent context layer for the MAXESS project.

It exists to reduce context loss, prevent repeated mistakes, preserve important decisions, and make future execution cumulative rather than episodic.

This is not a transcript archive. It is a distilled operating memory.

## NORTH STAR

Create an AI mastery assessment experience that makes a person understand how they currently work with AI, recognize their strengths and highest-leverage opportunities, see a personalized path forward, and feel genuinely motivated to continue with Naya and NayaNET.

The Results experience should produce the reaction:

**“Holy shit. I understand myself and what I should do next.”**

## RESULTS PAGE ARCHITECTURE

The MAXESS Results page is a high-rise tower built above the existing NayaNET page code.

`nayanetpagecode` is the ground floor.

Rules:
- It is not an iframe.
- It is not a separate page visually placed below Results.
- It is literally part of the same page/document.
- Preserve its visual and interaction language.
- Build the Results experience above it.
- New elements must feel native to the same design system.

## NAYANET DESIGN DNA

The NayaNET foundation establishes a premium cinematic technology aesthetic:
- black / deep purple atmosphere
- luminous purple gradients
- metallic/silver highlights
- premium rounded geometry
- layered borders
- deep shadows and glow
- Inter/system typography
- circular icon treatment
- premium gradient buttons
- strong primary/secondary CTA hierarchy
- full-width composition
- responsive clamp-based sizing
- keyboard focus states
- reduced-motion support
- cinematic media treatment

Do not create a competing visual language above NayaNET.

## PREMIUM CONSISTENCY RULE

Every new:
- button
- icon
- bullet
- card
- graph
- status indicator
- section marker
- interaction
- animation

must feel like it belongs to the same product.

Icons may be reused as bullets, section markers, status signals, and instructional anchors.

## VISUALIZATION PRINCIPLE

Data should be experienced, not merely displayed.

Valid visual metaphors include:
- speedometers
- gauges
- thermometers
- red/amber/green status systems
- radar/fingerprint shapes
- dimensional polygons
- spectra
- progress journeys
- luminous score objects

Do not add visual effects merely because they look impressive.

Use:

WOW → curiosity → understanding → recognition → action

## INTERACTION PRINCIPLE

The page should feel:
- alive
- electric
- powerful
- helpful
- useful
- premium

But never chaotic.

Motion must reinforce hierarchy and comprehension.

## AUTHENTICITY RULE

Never label an artifact `9.5`, `10`, `AAA`, or similar unless the finished experience has actually been evaluated against the relevant quality criteria.

Target score = acceptance criterion.

Target score ≠ filename.

## PRESERVATION RULE

Preserve working/high-quality foundations.

Improve what is weak without destroying what is strong.

For Results specifically, use existing NayaNET code as the visual foundation and build above it rather than repeatedly replacing it with unrelated implementations.

## COMPOUNDING LEARNING LOOP

DO → OBSERVE → SCORE → QUESTION → LEARN → UPDATE → APPLY → VERIFY → TEACH

Every meaningful correction should be converted into a reusable principle when appropriate.

## RECENT HIGH-VALUE LESSONS

### Growing Lesson 001
Visual optimization must improve the actual experience, not merely produce isolated polish.

### Growing Lesson 002
Oscar-style critique must become explicit correction, not commentary. Scorecard → identify weakness → implement → verify.

### Growing Lesson 003
A 10-star or release claim requires a live/product-level gate. The finished rendered experience, not merely source code, determines the truth.

### Growing Lesson 004
The system must compound learning. Corrections reveal reusable principles. Preserve them in the knowledge bank and consult them before future execution.

## CURRENT CRITICAL INSIGHTS

1. Context is often the real bottleneck.
2. Persistent project memory reduces repeated mistakes.
3. A strong existing foundation should be extended rather than replaced.
4. Visual consistency creates perceived premium quality.
5. Data visualization should communicate meaning, not decorate numbers.
6. WOW must increase comprehension or emotional impact.
7. A product should feel alive without becoming chaotic.
8. Build design systems rather than isolated visual tricks.
9. Corrections should update the system, not only the current artifact.
10. Every significant action should improve both the artifact and the process that creates future artifacts.

## PRE-ACTION CONTEXT PROTOCOL

Before substantial execution:

1. Consult this knowledge bank.
2. Consult the applicable master directive/specification.
3. Review the most recent relevant Growing Lessons.
4. Review the current source artifact and its dependencies.
5. Identify what must be preserved.
6. Identify what is known to be weak.
7. Identify assumptions that require verification.
8. Execute the smallest coherent change that advances the complete goal.
9. Verify the actual result.
10. Record new reusable learning.

## DO NOT REPEAT

- Do not patch multiple mediocre pages together and call the result finished.
- Do not create a fake 9.5 artifact because the target is 9.5.
- Do not build a visually unrelated Results page beside NayaNET.
- Do not iframe the NayaNET ground floor when the requirement is one continuous page.
- Do not sacrifice architecture for visual polish.
- Do not sacrifice visual quality for technical convenience when the foundation can support both.
- Do not treat user corrections as disposable.
- Do not rely exclusively on current-chat context when persistent project knowledge is available.

## DEFINITION OF SUCCESS

Success means:

**The user experience is genuinely excellent, technically sound, coherent with the NayaNET foundation, personalized from authoritative data, useful in practice, visually memorable, accessible, responsive, and honestly deserving of its score.**

And the process itself becomes smarter after every meaningful iteration.
