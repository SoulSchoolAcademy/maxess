# MAXESS MASTER DIRECTIVES

## 1. Truth before appearance
Never optimize a label, filename, or claimed score. Optimize the actual product and verify it.

## 2. Understand before executing
Before substantial work, consult `CURRENT-TRUTH.md`, relevant knowledge, prior lessons, current UI, and the applicable scorecard. Context is a first-class engineering dependency.

## 3. Preserve what works
When a strong existing foundation exists, preserve it and build on top of it. Do not replace a working system merely to make the implementation easier.

## 4. NayaNET ground-floor rule
`nayanetpagecode` is the canonical visual and interaction foundation for the bottom of the Results page. Do not iframe it. Do not make a parallel page. Build the MAXESS tower above it and physically inline it at production build time.

## 5. One visual language
Buttons, icons, bullets, cards, charts, typography, borders, colors, gradients, motion, spacing, and interaction states must feel like one premium system.

## 6. Cinematic revelation
The Results experience should create recognition, emotional impact, and curiosity. Reveal information progressively. Give the score and personal pattern room to breathe.

## 7. Data becomes action
Every major insight should answer: What does this mean? Why does it matter? What should I do next?

## 8. One clear next move
Avoid overwhelming users with long lists. Prefer one high-value next action per dimension/archetype, with deeper detail available when useful.

## 9. Naya is the continuation
Naya should appear as the natural next chapter after the user understands the result. The handoff should be prominent, simple, and context-aware.

## 10. Authoritative result data
Never fabricate a user's score, dimension, or personalized outcome. Render from the authoritative MAXESS result object.

## 11. Accessibility and resilience
Support keyboard focus, semantic structure, reduced motion, responsive layouts, and graceful missing-data states.

## 12. Build systems, not patches
Prefer reusable design tokens, configuration-driven data, shared components, and build pipelines over isolated hacks.

## 13. Learn continuously
Use DO → OBSERVE → SCORE → QUESTION → LEARN → UPDATE → APPLY → VERIFY → TEACH. Valuable corrections become reusable knowledge.

## 14. AAA release standard
AAA requires functional correctness, emotional and visual quality, personalization, maintainability, responsiveness, accessibility, trustworthy data, clear next action, and a coherent relationship between the whole experience and the NayaNET foundation.

## 15. Never stop at “looks good”
Attack the result. Look for confusion, friction, repetition, inconsistency, weak hierarchy, fake personalization, dead ends, fragile code, mobile problems, and unfinished states.
