## PRODUCT / SYSTEM MEMORY
When creating durable product decisions, add or update a clearly named file under `docs/` or `.naya/memory/` and add it here.

Recommended categories:
- Product vision and positioning
- Architecture and data contracts
- Assessment definitions
- Results experience specification
- Naya roles and capabilities
- Brand/content rules
- Deployment and infrastructure
- Known constraints and lessons
- Release history

## MEMORY RULE
Conversation is temporary. Repository memory is durable.
A decision that is important enough to affect future work should be written down.

## MEMORY QUALITY
Good memory is:
- Specific
- Current
- Actionable
- Scoped
- Date/version aware when needed
- Linked to related files

Avoid dumping raw conversation transcripts into memory. Capture decisions, rationale, constraints, and acceptance criteria.
