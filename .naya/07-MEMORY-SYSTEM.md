# 07 — NAYA SMART MEMORY SYSTEM

Status: AUTHORITATIVE PROJECT MEMORY PROTOCOL
Version: 1.0
Scope: All consequential AI work in MAXESS and connected Naya/Human Maximus systems.

## PURPOSE

The repository is not only source control. It is persistent operational memory.

Conversation is temporary. Repository memory is durable.

The purpose of this system is to make each meaningful execution improve the next one without allowing memory to become a pile of unfiltered notes.

## NORTH STAR

> **Every meaningful execution should make the next execution faster, clearer, safer, more accurate, and more excellent.**

The system learns through:

**OBSERVE → NOTE → CLASSIFY → SYNTHESIZE → PROMOTE → APPLY → VERIFY**

## MEMORY PRINCIPLES

1. Record useful learning, not conversation volume.
2. Preserve the distinction between observation, lesson, pattern, and permanent rule.
3. Never promote a one-off event into permanent law without sufficient evidence or clear general applicability.
4. Every permanent learning must improve future outcomes without weakening truth, safety, flexibility, or the North Star.
5. Prefer concise maps and links over duplicated documents.
6. Archive raw history rather than allowing active memory to become cluttered.
7. Daily synthesis compresses daily experience into reusable context.
8. Weekly synthesis compresses daily synthesis into higher-level patterns.
9. Permanent knowledge changes future behavior only when it earns promotion.
10. A failure is not fully learned until the system becomes harder to fail in the same way again.

## MEMORY LEVELS

### LEVEL 1 — RAW NOTE
What happened.

### LEVEL 2 — OBSERVATION
What appears significant.

### LEVEL 3 — LESSON
What the event teaches us.

### LEVEL 4 — PATTERN
A reusable behavior or recurring failure/success pattern.

### LEVEL 5 — SAFEGUARD
A concrete rule, test, gate, checklist item, or process change that prevents recurrence or preserves success.

### LEVEL 6 — PERMANENT KNOWLEDGE
A durable principle that should influence future executions across projects or repeatedly within this project.

### LEVEL 7 — GOVERNANCE CHANGE
A lesson important enough to update the Digital Codex, Naya Law, Master Operating Protocol, or another authoritative governance document.

## PROMOTION TEST

Before promoting a lesson, ask:

- Is it true?
- Is it useful?
- Is it relevant to future work?
- Is it generalizable?
- Is it supported by evidence or strong reasoning?
- Does it conflict with a higher-priority rule?
- Could it create unintended constraints?
- Does it belong in memory, or should it remain a project-specific note?

If uncertain, keep it at the lower memory level until more evidence exists.

## SMART NOTE COMMANDS

Natural-language commands are supported conceptually and operationally:

- “Add a note about this conversation.”
- “Record what we learned.”
- “Save this lesson.”
- “Make this a permanent safeguard.”
- “What did we learn today?”
- “Synthesize today.”
- “Update the memory.”
- “What should change because of this?”

The executor must classify the requested memory rather than blindly appending text.

## DAILY LOOP

During work:

**EVENT → SMART NOTE → CLASSIFY → LINK TO PROJECT**

At the end of a workday:

**RAW NOTES → DAILY SYNTHESIS → PROMOTE IMPORTANT LESSONS → UPDATE SAFEGUARDS**

## WEEKLY LOOP

At the end of a meaningful work period:

**DAILY SYNTHESIS FILES → WEEKLY SYNTHESIS → PATTERNS → PERMANENT KNOWLEDGE → SYSTEM UPDATES**

## LEARNING SAFETY

Never learn backwards.

A bad outcome must not automatically produce a bad general rule.

Before permanent promotion, evaluate:

**TRUTH → RELEVANCE → GENERALIZABILITY → BENEFIT → COMPATIBILITY → VERIFICATION**

## REQUIRED FAILURE LOOP

When a material failure occurs:

**ACKNOWLEDGE → ROOT-CAUSE → FIX → VERIFY → RECORD → SAFEGUARD → RETEST**

Repeated failure requires escalation.

If the same failure class repeats four times, enter ROOT-CAUSE LOCKDOWN and investigate the process, not merely the latest symptom.

## REQUIRED SUCCESS LOOP

When a meaningful success occurs:

**OBSERVE → IDENTIFY WHY → RECORD → TEST REPEATABILITY → PROMOTE IF VALID → REUSE**

Success should become a reusable pattern rather than a forgotten lucky result.
