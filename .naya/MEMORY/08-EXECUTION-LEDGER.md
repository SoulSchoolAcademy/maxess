# EXECUTION LEDGER

Every consequential execution receives a unique execution number.

## PURPOSE

The ledger makes iteration count, material change, verification, failures, and learning traceable.

## REQUIRED ENTRY

### EXECUTION #

### DATE

### PROJECT / AREA

### DIRECTIVE

### VERSION / TARGET

### AUTHORITATIVE SOURCE

### BASELINE

### REQUIREMENTS COUNT

### MATERIAL CHANGES MADE

### FILES / COMPONENTS CHANGED

### PROTECTED FUNCTIONALITY

### TESTS RUN

### OSCAR FINDINGS

### LIVE / TARGET VERIFICATION

### QUALITY SCORE

### STATUS
DRAFT / EXECUTED / BLOCKED / VERIFIED / FROZEN

### FAILURES

### LESSONS

### SAFEGUARDS CREATED OR UPDATED

### NEXT EXECUTION

## ZERO-CHANGE RULE

If a requested implementation produces no material change, record:

`STATUS: BLOCKED — ZERO-CHANGE EXECUTION`

Do not report the execution as complete.

## ITERATION RULE

Version numbers and execution numbers are not interchangeable.

Execution # measures attempts/iterations.

Version measures the artifact state.

A new execution must explicitly state both when both exist.
