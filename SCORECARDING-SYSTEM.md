# MAXESS SCORECARDING SYSTEM

## Purpose

Score the real product, not the intention, filename, or amount of code.

## Core loop

CREATE → SCORE → IDENTIFY THE GAP → IMPROVE → RE-SCORE

## Evaluation categories

| Category | Weight |
|---|---:|
| Concept & Vision | 15% |
| User Journey / Experience | 15% |
| Visual Design & Brand | 12% |
| Personalization | 12% |
| Code Quality & Structure | 10% |
| Technical Implementation | 10% |
| Conversion / Next Step | 8% |
| Documentation & Process | 8% |
| Maintainability | 5% |
| WOW / Emotional Impact | 5% |

## AAA interpretation

9.5–10.0: genuinely exceptional and release-ready; no obvious major weakness.
9.0–9.49: excellent but still has meaningful improvement opportunities.
8.0–8.99: strong product with noticeable gaps.
7.0–7.99: good foundation, but execution gaps materially affect the experience.
Below 7.0: significant work remains.

## Hard gates

A product cannot honestly receive AAA if any of these fail:

- authoritative data integrity
- core user journey completion
- responsive/mobile usability
- accessibility basics
- Naya handoff
- maintainable source of truth
- canonical NayaNET ground-floor integration
- no misleading claims about completion or score

## Review questions

1. Does the user immediately understand what they are seeing?
2. Does the experience create a meaningful recognition moment?
3. Does personalization visibly come from the user's data?
4. Does every major section earn its space?
5. Is the next action obvious?
6. Does the page feel like one coherent premium system?
7. Does the NayaNET ground floor feel native to the tower above it?
8. Does the experience work without motion?
9. Does it work on mobile?
10. Is the code maintainable by the next engineer or AI?
11. What is the weakest 20%?
12. What would make the experience unforgettable without making it noisy?

## Truth rule

Never round an implementation up to 9.5 because it is close. The score is an honest assessment of the finished rendered experience.
